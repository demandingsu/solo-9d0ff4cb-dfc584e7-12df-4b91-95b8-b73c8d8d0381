# 招标延期核对助手

采购代理人核对招标延期时，需要找回原公告与后续更正公告。本工具输入招标公告**列表页地址**，
沿同站点“下一页”自动抓取详情页，按字段标签读取项目编号、公告类型、发布时间、投标截止时间，
按**项目编号归并**、按**发布时间先后**处理，并在浏览器展示每个项目的当前结果与全部公告链接。

新增**中标联合体候选人核对**：发布中标结果前，核实中标联合体是否出现在同标段候选人公示中。
输入公告**目录地址**，沿同站分页读取候选人公示与中标公告详情，按标段编号、候选序号提取联合体
成员的“名称＋统一社会信用代码”，逐标段给出 **入围 / 未入围 / 待核实**。

## 处理规则（招标延期核对）

| 情形 | 处理结果 |
| --- | --- |
| 更正/延期公告**明确写出新的投标截止时间** | 用新时间**替换**旧时间，状态为“有效” |
| 较晚公告**声明延期却未给出新时间** | 状态标为 **“待核实”**，不再显示/沿用旧截止时间 |
| 所有公告均未公布截止时间 | 状态为“未公布” |
| 只有原始招标公告 | 沿用原截止时间，状态为“有效” |

同一项目的全部公告（原公告、更正、延期）按发布时间升序保留，并附原文链接，便于回溯核对。

## 处理规则（中标联合体候选人核对）

以同一联合体的“**名称＋统一社会信用代码**”配对构成集合，与中标联合体整体比对：

| 情形 | 核对结果 |
| --- | --- |
| 中标联合体与某一候选序号的成员集合**完全一致** | **入围**（成员顺序不影响匹配） |
| 成员名称相同但信用代码不同（**同名异码**） | **未入围**，并在说明中标注差异 |
| **仅牵头人相同**、其余成员不同 | **未入围**，并在说明中标注差异 |
| 与任何候选序号都不一致 | **未入围** |
| 同标段**候选人公示缺失**，或公示/中标**详情抓取失败** | **待核实**，附失败链接与原因 |

逐标段展示双方来源：中标公告的联合体成员表、候选人公示的各候选序号成员表（入围的候选序号
高亮标注），公告链接均经 `/view` 代理打开。同一标段出现多份中标公告时，以发布时间最新的一份比对。

│       ├── parser.py           # 按字段标签解析详情（表格/dl/label/正文兜底）
│       ├── merger.py           # 按项目编号归并、按发布时间处理截止时间
│       ├── consortium_crawler.py   # 公告目录抓取，筛出候选人公示/中标公告
│       ├── consortium_parser.py    # 按标段编号切分详情，提取联合体成员（名称+信用代码）

│       └── templates/
│           ├── index.html          # 延期核对入口 + 联合体核对入口
│           └── consortium.html     # 逐标段核对结果页

│   ├── Dockerfile              # 构建时运行 generate_site.py 生成页面
│   ├── nginx.conf
│   ├── generate_site.py        # 延期场景 11 条公告 + 联合体场景 8 页中标类公告

    └── test_consortium_end_to_end.py   # 联合体核对端到端测试

## 用 Docker Compose 启动

```bash
docker compose up --build
```

- 网页应用：<http://localhost:8000>
- 示例站点（宿主机直连）：<http://localhost:8080>

**招标延期核对**：在首页第一个输入框填入

```
http://example-site/list/page_1.html
```

**中标联合体候选人核对**：在首页第二个输入框（或 `/consortium` 页）填入

```
http://example-site/bidlist/page_1.html
```

（均为容器内服务名地址，网页后端可直接抓取。）

联合体核对结果页展示：

1. 抓取概况：遍历的目录页、候选人公示/中标公告份数、抓取失败详情（含锚文本与错误）、跳过链接；
2. 逐标段结果：标段编号、状态徽章（入围/未入围/待核实）、说明；
3. 双方来源：中标联合体成员表（角色/名称/统一社会信用代码）与候选人公示各候选序号成员表，
   原文链接经 `/view` 代理打开，离线即可在浏览器中回溯核对。

> 公告链接默认指向容器内网地址（如 `http://example-site/...`），宿主机浏览器无法直接打开，
> 因此页面链接统一经过网页后端的 `/view` 代理打开；示例站点本身也映射在 8080 端口可直接浏览。

## 示例站点覆盖的场景（中标联合体候选人核对）

目录 `bidlist/` 共两页，含 8 页真实详情与 2 个故意缺失（404）的详情链接：

| 标段编号 | 场景 | 预期结果 |
| --- | --- | --- |
| BD-2026-101 | 中标联合体 = 第二中标候选人，成员行顺序被打乱 | **入围**（成员顺序不影响匹配） |
| BD-2026-102 | 中标联合体成员与第一中标候选人同名，但信用代码不同 | **未入围**（同名异码） |
| BD-2026-103 | 中标联合体仅牵头人与第一中标候选人相同 | **未入围**（仅牵头人相同） |
| BD-2026-104 | 只有中标公告，无同标段候选人公示 | **待核实**（候选资料缺失） |
| BD-2026-105 | 中标公告详情页 404 | **待核实**（中标公告抓取失败） |
| BD-2026-106 | 候选人公示详情页 404 | **待核实**（候选人公示抓取失败） |

其中 `cand_102_103.html` 为一份公示覆盖两个标段（BD-2026-102、BD-2026-103），
用于验证按“标段编号”切分多标段页面；各页成员表使用不同表头别名
（成员名称/单位名称/企业名称/供应商名称等），验证解析器的标签适配能力。

## 解析器的字段适配

**招标公告详情**：不绑定固定模板，按“字段标签 → 值”依次尝试：

1. 表格行（`th/td`，含一行两对字段）；
2. `dl/dt/dd` 定义列表；
3. `label` + 输入控件（`input/textarea/select`）；
4. 正文中的“标签：值”段落。

标签支持常见别名（如“招标项目编号/项目编码”“投标文件递交截止时间/开标时间”等），
标签缺失时再用正则兜底；识别不到项目编号的页面会被跳过并记入“跳过链接”。

**候选人公示 / 中标公告详情**：

1. 先按标题/公告类型区分“候选人公示”与“中标公告”（“中标候选人公示”优先判为公示）；
2. 按“标段编号：XXX”锚点把页面切分为若干标段区块（单标段页面支持字段标签形式给出标段编号）；
3. 区块内优先解析成员表格：自动展开 `rowspan/colspan`，按表头别名映射
   候选序号/成员角色/成员名称/统一社会信用代码四列，候选人公示按候选序号分组；
4. 表格未产出成员时，回退到正文段落的“名称：… 统一社会信用代码：…”写法；
5. 信用代码按 18 位统一社会信用代码字符集提取，比较前统一去空白并转大写。

## 安全与边界

- 仅跟随与入口**同站点**（协议+主机+端口一致）的“下一页”和详情链接，跨站链接跳过并记录；
- 只允许 `http(s)`，拒绝 `file://` 等协议；
- 上限：列表页 10 个、详情页 100 个、单请求超时 15 秒；
- 联合体核对只读取候选人公示/中标（成交）公告，招标、更正、延期等无关公告不抓取并记入跳过链接；
- `/view`、`/asset` 代理同样只转发 `http(s)` 目标。
